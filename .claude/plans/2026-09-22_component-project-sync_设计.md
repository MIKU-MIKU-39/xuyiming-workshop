# 组件发布后同步工程设计

维护：Xuyiming。用户已确认本方案；本次只修改个人 marketplace 源仓库，不更新已安装技能，不发布业务组件。

## 行为边界

- 原有明确发布请求仍直接调用 Wukong；成功发布后另行询问是否同步工程。
- 以本次实际成功的完整版本号为依据：后缀含 VO 对应 Vone，含 PLA 对应 Poppo；只有一个明确平台版本只建议该平台；无标识、冲突、多候选需用户明确映射。
- Vone 默认目录 `/Users/vshow/Desktop/Work/vone`，Poppo 默认目录 `/Users/vshow/Desktop/Work/poppo`。路径可按用户当前指示覆盖；目录缺失时询问，不克隆或猜测。
- 同步审批包含切换 develop、拉取最新远端、修改 Podfile、创建本地提交；推送必须在提交完成后独立询问。

## 实现

新增 `sync_projects.py`：classify 输出平台候选；plan 只读检查；sync 在明确调用后执行同步。辅助脚本不提供 push，防止把同步批准误当作推送批准。

Git 限制：仓库根目录、干净工作区和暂存区、无进行中的 Git 操作、明确的 develop 和远端。fetch 后只允许快进；develop 存在未推送提交或分叉则停止。不得 reset、stash、强推或覆盖用户改动。

Podfile 通过 Ruby 标准库 Ripper 做静态分词和语法校验，不加载或执行 Podfile。只支持独立单行的字面量版本声明；同组件及 subspec 的一致版本可一起替换。动态版本、源引用、条件表达式或冲突版本停止并说明。只提交 Podfile，不运行 pod install，不改锁文件。

提交标题包含组件和版本，正文保留本次发布信息。输出提交 SHA、远端基线及待推送状态。双项目先分别预检，再逐个执行；失败时报告已经完成的本地提交，不自动回滚或重试。

## 验证与交付

临时 Git 仓库和本地 bare remote 覆盖版本分类、Podfile 保真替换、快进同步、异常状态和从不自动推送。独立技能前向测试检查对真实请求的决策。通过结构校验和全量回归后推送 marketplace main，发布插件 0.2.0；交付手动升级命令并提示同名独立 skill 不会被插件升级覆盖。
