# 发布后选择与隔离提交

维护：Xuyiming。用户已确认采用独立暂存区方案，并授权完成后提交、推送和本地安装验证。

## 背景与目标

组件上传成功后，通过宿主选择框提供「同步提交并推送」「仅提交」「不提交也不推送」。选择一直接授权本次明确工程/版本的提交和推送；选择二只提交；选择三不修改主工程；未回答不授权任何操作。

主工程可能已有已暂存、未暂存和未跟踪代码。本次提交必须只包含目标组件的 Podfile 字面量版本变化，其他代码及其暂存状态保留，包括同一 Podfile 的不相关修改。

## 方案决策

采用临时 GIT_INDEX_FILE 从远端 develop 基线构建提交，真实 index 只同步目标版本，不把用户其他修改带入提交。相较整体暂存 Podfile，可隔离同文件改动；相较一律拒绝脏工作区，可继续处理不相关改动。不使用 stash、reset、强制切换或跳过 hook。

## 架构与模块设计

- SKILL.md 与 project-sync.md：发布成功证据、弹框授权、版本映射与异常边界。
- sync_projects.py：静态 Podfile 解析、脏工作区预检、隔离提交、显式 --push 后的远端核验与推送。
- test_component_sync.py：仅使用临时仓库和本地 bare remote 做可观察行为测试。
- 插件声明、UI 元数据、说明：同步升级至 0.2.4。

## 关键接口定义

保留 plan_sync 与 sync_project 原有参数兼容性；sync_project 增加默认 false 的 push 参数，CLI sync 增加 --push。只有选择一传该参数。返回记录包含实际 commit、base_commit、pushed 与保留本地改动状态。

## 数据流与错误处理

只读预检 → 等待明确选择 → fetch → 基线检查 → 独立 index 创建目标提交 → 精确核验提交内容/父节点/日志 → 更新真实 index 的目标版本 → 按选择核验远端并推送。

有未提交改动时，要求当前已处于与远端一致的 develop；需要切分支或快进时停止，不搬移用户改动。目标组件声明与基线不同、动态声明、合并状态、未推送提交/分叉均停止。提交 hook 或签名失败保留现场；提交或 index 在运行中变化停止，禁止推送。推送前确认唯一且一致的 fetch/push URL、远端仍等于基线，显式推送精确提交 SHA，不强推。结果不明只核验，不自动重试。

## 测试策略

覆盖同文件 staged/unstaged 混合、其他文件 staged/unstaged/untracked、目标声明冲突、脏工作区切分支/落后远端、hook 失败与改写、无变更、仅提交不推送、显式推送、远端变化阻断。验证真实提交树和用户差异，不仅匹配文档措辞。运行既有测试、市场/技能校验；安装后比对缓存与已推送源码并重复回归。
