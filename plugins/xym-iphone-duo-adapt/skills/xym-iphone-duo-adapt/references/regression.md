# 独立回归协议

Created by Xuyiming on 2026/10/29.

这是每批 1–3 页的执行门禁，不是可省略的结尾清单。代码审核与 UI 回归分别给结论，缺任一项都不能放行。

## 基线与环境

修改前记录工程、branch/HEAD、原有工作区 diff、scheme、构建 SDK、最低系统版本、配置、bundle ID、模拟器 UDID/名称/运行时、页面入口与测试数据。已有未提交改动也是基线的一部分，不能 reset/stash 掉再冒充原版。

基线和改后使用同一可复现的数据/账户状态、主题、语言、字号、运行时与布局姿态。动态视频用同一内容的同一暂停时间点；列表用一致数据或明确标出动态内容差异。不得为了截图替换真实布局、隐藏遮挡控件或在生产代码加入测试开关。

优先用项目已有 UI 测试、测试路由或宿主 UI 自动化。使用工具前核实当前版本帮助；不能杜撰 fold/tap 命令。以下仅为可用时的命令形状，参数来自现场查询，不使用固定 UDID 或盲目的 `booted`：

```sh
xcrun simctl list devices available --json
xcrun simctl io <device-udid> screenshot <absolute-output.png>
```

有 RTK 规则时加 `rtk proxy`，构建/测试遵从本机要求的包装器。启动、安装和操作限选定模拟器，不擦除数据、不重启所有设备、不卸载其他 App、不改变全局 Xcode 选择。缺权限先按宿主机制申请；缺工具/运行时则报告，不静默下载大型运行时或伪造设备。

iPhone Duo 的 Open/Closed/Partially Open、旋转等优先通过实际可用的 Device Hub 控件或经本机帮助证实的接口操作。记录实际姿态证据，屏幕宽高变化本身不能证明已进入半折状态。普通 iPhone 不能代替 Duo；不同 iOS 版本设备各自使用同版本的改前/改后基线，不能把跨版本系统外观变化算作代码回归。

## 每批回归矩阵

| 设备/状态 | 必查项目 |
| --- | --- |
| 普通 iPhone，原有支持方向 | 原 UI 的颜色、位置关系、间距、大小、圆角、字体/图标，导航与按钮点击 |
| Duo 外屏 Closed | 非对称安全区、侧边系统栏、列表宽度、返回/Tab/重要操作可达 |
| Duo 内屏 Open 横向与竖向 | 开合后的实时尺寸、系统栏换轴、所有边缘、列表/详情和弹层布局 |
| Duo Partially Open，相关横/纵分隔 | 对本批存在跨折痕风险的列表、悬浮按钮或自定义区域检查 actual division，位移与恢复 |
| 状态转场 | 同一进程中开→合→开、旋转、进入二级→返回、Tab 来回切换；不靠重启掩盖旧 frame |
| 涉及输入/遮挡/视频的页 | 键盘开关、草稿、相机相关 occlusion、弹层遮挡、滚动/播放状态；按页面实际功能验证 |

半折/相机等不适用项必须写理由。页面包含该功能但无法操作时是 blocked，不是 N/A。覆盖实际受影响页面，不因首页看起来正常而跳过详情或返回路径。

## UI 判定

截图必须实际打开查看，检查完整页面及重要控件局部。结合 UI 层级/坐标和点击、滚动结果确认：无非预期遮挡、重叠、越界、裁剪、拉伸、文字截断或不可触达操作。预期的图片 Fill 裁剪需按原内容策略判断，不能把业务设计误判成缺陷。

普通 iPhone 以同尺寸前后对照为严格基线，不能靠不同缩放/裁切对齐掩盖偏差。Duo 可接受经记录的新增画布、必要重排与系统栏换轴；颜色、字体、图标、圆角和操作能力不因此放宽。额外设计改变须用户确认，不能由 reviewer 自行豁免。

像素差可辅助定位，但抗锯齿、动态内容、时间和系统动画差异需要人工辨别；不设置无来源的统一百分比阈值，也不只用「差异小」判通过。明确指出允许变化的控件、原因与区域，不能整屏遮罩掉差异。

## 子 Agent 任务包

每批用真实值补齐以下材料，再派发给独立 reviewer；这是一段任务模板，不是预填结论：

> 你负责本批的只读代码审核与真实模拟器 UI 回归。你不是唯一操作代码库的 Agent，不要修改、撤销或暂存业务文件；只在指定证据目录写报告/截图。本批有 1–3 个页面，页面名称、入口路径、代码基线和精确 diff、构建标识、可用设备/运行时、数据条件、改前截图及证据目录由主 Agent 随任务提供。按 xym-iphone-duo-adapt 的 adaptation.md 和 regression.md 执行。核对补丁是否仅含必要适配、有无不必要的重写/防护/业务修复或视觉改变。实际操作 Duo 和普通 iPhone，逐页检查遮挡、重叠、越界、裁剪、按钮可点击及导航/状态保持，并打开前后截图对比颜色、位置、间距、大小、圆角。给每个问题提供文件行号或截图位置、复现步骤、设备/姿态及最小修正建议。无访问能力、基线或证据时明确 blocked，不伪造运行结论。分别报告代码和 UI 的 pass/fail/blocked，最后给本批是否允许进入下一批。

主 Agent 保留 reviewer 标识和任务包，委派后不同时操作相同 UDID。回归 Agent 可复用以复验同批修复，但必须拿到最新 diff、构建和截图；不能沿用旧 pass。子 Agent 不应再次派发修改者去替自己验收，也不自行批准业务提交/推送。

## 闭环

用 [批次记录](../assets/batch-review.md) 写结果。`fail`：主 Agent 只修范围内适配问题，再交同一 reviewer 验证失败项及关联双机型路径。`blocked`：报告缺项，不扩展下一批；其他已完成证据可保存，但不能宣布全批通过。`pass`：代码范围与相关 UI/交互均有证据，通过后才开始下一批。发现已有业务缺陷单列报告，不把它混入本次补丁。
