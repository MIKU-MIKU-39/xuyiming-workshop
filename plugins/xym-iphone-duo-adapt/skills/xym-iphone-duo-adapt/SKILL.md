# Xym iPhone Duo Adapt

Created by Xuyiming on 2026/10/29.

默认只修适配逻辑：保留既有 UI、业务行为、页面对象和技术栈。用户只要求解释、制定方案或编辑本技能时，不修改业务工程，也不宣称已完成业务 UI 回归。

## 1. 明确范围与改前基线

- 使用用户指定工程；未指定则先核实当前目录是否为目标。确认构建入口、scheme、启动方式及目标页面路由，保留已有修改。范围缺失时询问，不把市场仓库当业务工程。
- 读取项目 AGENTS/CLAUDE 规则和适用的 iOS 语言规范；使用已有构建、截图和 UI 测试设施，不为本任务安装新框架。查明页面实际采用 UIKit、Masonry、Texture、SwiftUI 或其他容器，再按原栈修改。
- 先读 [适配要点](references/adaptation.md) 与 [回归协议](references/regression.md)。需要核对 API 或出处时读 [资料索引](references/sources.md)，并以项目实际 SDK 声明为准。
- 记录构建 SDK 与 deployment target，两者分开处理。只读核实可用的 iPhone Duo 和普通 iPhone 设备/运行时。新 SDK、Scene 或方向配置会影响多个页面，先说明实际影响，不能暗中升级工具链或最低系统版本。
- 列出基础页面、二级详情、弹层、Tab 切换、push/pop/present/dismiss 路径和共享布局容器。修改前在同数据、主题、语言、字号、姿态和运行时条件下采集截图及关键交互状态，保存代码基线；不能以不同数据或旧 SDK 截图声称精确视觉对比。
- 缺运行时、登录条件、页面入口、基线或 UI 操作权限，先请求所缺条件；可以继续只读定位，不把不可测页面标为通过，也不静默换成 iPad 代替 Duo。

## 2. 每批只修正 1–3 个页面

先为本批列出「观察到的问题 → 布局原因 → 最小修改位置 → 回归设备/状态」。按页面计数，不按文件计数；复杂页优先单页一批。

允许的修改包括当前容器 bounds、四边安全区、必要约束/frame 更新、列表项尺寸与布局失效、现有系统栏项配置、实际遮挡处的局部 ReservedRegion 避让。优先沿用现有生命周期、约束、样式常量和公开 API。

不顺手重写页面/播放器/导航结构，不改业务数据流、请求、路由、模型、文案或默认视觉；不做无关 crash 修复、代码清理、性能重构，也不建立全局适配管理器。只在系统 API 可用性、权限、外部数据等真实边界验证，不对内部已建立的约束重复防护。低概率特殊分支若没有复现证据，不加兜底；确需扩展范围时先解释具体问题与成本并取得批准。

保持原颜色、字体、图标、圆角、间距、触控尺寸及相对位置。不要把整体缩放、缩小按钮/字体、裁剪、隐藏操作项或全局禁用竖栏当作消除遮挡的方法。不要照抄演示中的 160/760/12 pt。Duo 的必要可用区域变化和重排需明确记录，不能借大屏改版。

共享容器一次影响超过 3 页时先列出影响集，保持一个最小共享补丁，按每组最多 3 页逐批回归所有受影响页面；在影响集验收前不叠加其他页面修改，不把「一个文件」算作「一个页面」。

## 3. 必须派发独立子 Agent 审核与 UI 回归

每完成本批 1–3 页的修改，先构建，再立即派发/唤醒回归子 Agent，不能累积更多页面后才统一 review。使用宿主的子 Agent 工具（例如 `collaboration.spawn_agent` / `followup_task`），不要擅自新建用户任务来代替子 Agent。

- 主 Agent 负责业务文件修改与修复；回归 Agent 只读业务代码，只写本批证据/报告目录。告知其并非独占代码库，不覆盖、撤销或暂存别人的改动。
- 按 [回归协议中的任务包](references/regression.md#子-agent-任务包) 提供代码基线、精确 diff、页面/路由、前后构建与数据条件、截图、设备和例外。首次 reviewer 使用独立上下文，不把主 Agent 的「已通过」判断当作结论。
- 回归 Agent 必须同时完成代码审核、实际模拟器操作和视觉检查。Duo 覆盖外屏、内屏横竖向及与本批有关的折叠/遮挡状态；普通 iPhone 做同条件视觉回归。只构建、只读 diff 或只看截图缩略图均不能给 UI 通过。
- 同一模拟器同一时刻只有一个操作方；回归期间主 Agent 不改本批代码或操作该设备。修复后发送新 diff/构建标识，要求 reviewer 重新运行失败路径及受影响的双机型用例。
- reviewer 返回 `pass` / `fail` / `blocked` 及证据。未提供真实截图和交互结果不能 pass；能力/权限缺失写 blocked，不声称子 Agent 或 UI 回归已经执行。

没有子 Agent 工具时停在回归门禁并说明缺口，不自行审查后冒充独立验收。失败时只修本次适配引入或范围内的 UI 问题；发现既有业务缺陷单独报告，不顺带修复。全部本批阻塞消除并经 reviewer 复验后才进入下一批。

## 4. 完成条件

用 [批次记录模板](assets/batch-review.md) 保存可复现证据。所有批次必须明确列出受影响页面、源代码/构建标识、双机型结果、视觉差异、交互结果、子 Agent 标识及复验结论；没有覆盖的姿态/页面明确写出。

最后核对变更均为必要适配、没有遗留业务测试开关或无关代码，并按项目现有格式/注释检查规则处理本次差异。报告已验证与未验证范围，附截图/报告路径。编译成功不等于 UI 通过，报告完整也不等于证据通过。仅用户明确要求时提交/推送业务代码；适配请求不自动授权组件发布或主工程版本同步。
