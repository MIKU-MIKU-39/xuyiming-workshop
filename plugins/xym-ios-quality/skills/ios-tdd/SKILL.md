# iOS TDD

读取项目现有测试、测试 target 和依赖注入方式，选择最小可观察行为。不要为了套 TDD 重构整个模块。

1. RED：先写一个能稳定描述预期行为的最小测试，运行并记录断言失败。缺依赖、编译错误或找不到测试不算业务失败，先修正测试设施。
2. GREEN：仅在用户要求实现/修复时做最小变更。只要求诊断时交付失败用例和根因，不自动修业务。
3. REFACTOR：去掉重复，保持公开契约；再次跑相关测试及必要回归。
4. 并发/生命周期用例使用可控调度、期望和有限超时；禁止无界信号量等待。内存问题检查 weak 引用释放，避免测试本身持有对象。
5. 从 xcresult 的权威计数报告 XCTest/Swift Testing 结果，覆盖率阈值使用项目配置。无设备/证书/测试 target 时明确说明验证缺口，不编造百分比。

构建可使用已安装 ios-build，或项目已有包装命令。没有任何工具也可写清复现步骤，但不得标成已执行。完整风险列表见 references/ios-checklist.md（相对插件根目录）。
