# 过度设计审查

确认 review（当前 diff）/ audit（指定仓库范围）/ debt（现存 SIMPLIFY 标记）。只读默认，不因为用户说“看看能否简化”就删除代码。

证据来自实现数量、真实调用方、替代的已有 API、必要兼容性和测试边界。检查：单实现且无边界价值的抽象、重复映射/封装、可读性差的状态层、未使用扩展点、重复造轮子。文件/函数过长仅是线索；阈值来自项目配置，不内置 400/40 等公司标准。
保留有实际价值的协议：测试隔离、ABI 边界、平台适配、安全约束和已确认多实现计划。不要为了减少行数牺牲可读性、错误处理或性能。
每条结果一段：位置 → 多余成本 → 证据 → 最小简化方案 → 保留理由/风险。没有足够收益就建议不动。correctness 问题单独标注，不能冒充本技能全面安全审查。
用户明确要求实施后再限定变更范围，保持行为测试通过；不自动提交。
