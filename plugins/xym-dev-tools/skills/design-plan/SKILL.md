# 需求到实施计划

先区分用户需要讨论、设计文档还是直接实现。读取相关入口和约束；识别已有明确决定，勿重新询问。

1. 列目标、非目标、验收证据和影响范围。只询问会实质改变方案的缺失信息。
2. 需要选型时给 2–3 个真实可行方案，比较复杂度、兼容性、运行成本和风险，给出推荐依据。
3. 涉及新授权/破坏性操作/外部写入时必须确认；普通已授权实现可按合理假设推进，不设无意义审批门槛。
4. 计划按可验证产物拆步，写清文件、数据流、测试、失败处理和回退边界。优先可独立验证的小步，不默认每步 commit/push。
5. 文档输出到用户指定或项目约定目录；缺少约定时先提出路径，不污染全局配置。文件作者使用 Xuyiming。

交付应能直接执行而非框架清单。已有批准后进入实现，不无限循环设计评审。
