# 崩溃复现与修复

先区分：仅分析 / 建复现 / 修复并验证。只要求分析时不改生产代码。

1. 整理 crash 版本、UUID、设备/系统、异常与触发线程；必要时用本插件 crash-symbolicate。读可信堆栈对应源码和调用者，列出事实、假设、反证。
2. 找到最小因果链：输入 → 状态/线程交错 → 失效对象/非法范围/异常。复现应触发同一失败机制，不用直接 throw/fatalError 伪造原崩溃。
3. 尽量用现有测试 target；真 UI/生命周期问题才建最小 Example 入口。加有限超时、清理和可控调度，不使用永久锁死主线程的“复现”。
4. 记录修复前失败次数/总次数、环境、日志；解释不稳定复现的限制。获得实现授权后才做最小修复，验证相同用例通过。
5. 回归检查调用约定、取消/重入、后台回调、对象释放、性能与共享组件影响。参考项目配置确定循环次数，不编造通用“跑一千次就安全”阈值。
6. 返回根因证据、最小修复、前后验证、未覆盖风险。无条件稳定复现做不到时明确降级，不声称闭环完成。
